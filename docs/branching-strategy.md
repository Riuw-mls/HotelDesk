

# Стратегия ветвления (Branching Strategy)

В этом репозитории используется простая стратегия ветвления Git для команды из двух человек.

Ветки:

- `main` — стабильная, готовая к выпуску ветка
- `feature/<name>` — новые функциональности
- `bugfix/<name>` — исправления ошибок
- `docs/<name>` — документация и обновления ADR

Примеры:

- feature/hotel-search
- feature/booking
- feature/admin-panel
- bugfix/booking-conflict
- docs/adr-001

Правила:

- Не работать напрямую в `main`.
- Одна задача = одна ветка.
- Имена веток должны быть понятными и описательными.
- После завершения работы объединять изменения в `main` через pull request/merge request.
- Перед объединением обеспечить обзор и проверку изменений.
